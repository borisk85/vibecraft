# /analyze-competitors

Анализ ТОП-3 конкурентов: UX, слабости, что строить лучше.

## Usage
`/analyze-competitors [keyword]`

## What it does

1. WebSearch "[keyword]" → взять ТОП-3 URL.

2. WebFetch каждого → анализ:
   - **Тип инструмента:** что именно делает (calculator/generator/checker/etc)
   - **UX:** сколько шагов до результата? Instant или нужен Submit?
   - **Mobile:** удобно на телефоне?
   - **Дизайн:** чистый или захламлен рекламой/навигацией?
   - **Фичи:** какие inputs/outputs? Чего не хватает?
   - **AI:** есть AI-компонент или чисто статичный?
   - **Объяснения:** объясняет результат или просто показывает число?

2b. **ТВОРЧЕСКИЙ ВЫБОР ФОРМАТА (обязательно, до BUILD BETTER) — не копировать формат конкурентов вслепую.**
   Конкуренты сделали калькулятор — НЕ значит, что мы тоже обязаны калькулятор. Продумать: какой формат продукта под этот запрос дает пользователю максимум ценности и отличает нас?
   Варианты: калькулятор · генератор · интерактивный визуализатор/график · тренажер/симулятор · чекер/тест · конструктор/builder · сравнитель · планировщик · конвертер · lookup · скачиваемый шаблон.
   Часто выигрыш не в «тот же калькулятор, но чуть лучше», а в ДРУГОМ формате или в гибриде (например калькулятор + визуализатор + сценарии). Зафиксировать выбранный формат и ПОЧЕМУ он бьет конкурентов сильнее, чем копия их инструмента.
   Это не «да/нет калькулятор», а творческое решение — в нем половина успеха сайта.

3. BUILD BETTER чеклист:

```
=== BUILD BETTER: [keyword] ===

Чего НЕТ у конкурентов:
- [ ] [Фича 1]
- [ ] [Фича 2]

Что у них плохо → наше решение:
- [ ] [Проблема] → [как решаем]

AI_VERDICT: YES / NO
Причина: [одна строка — почему нужен или не нужен Haiku]
Если YES: Haiku для [конкретный use case] — что именно улучшает

MUST-HAVE минимум:
- [ ] Instant result (без Submit)
- [ ] Mobile-first
- [ ] [Специфичное для этого типа инструмента]
```

**AI_VERDICT обязателен.** Не "если применимо" — всегда явный ответ YES или NO с причиной.

4. Save to `C:/Claude Code/niche-tools/sites/[slug]/COMPETITOR_ANALYSIS.md`

5. После сохранения — вывести коротко (без жаргона):
```
=== ЧТО СТРОИМ: [keyword] ===
Формат: [калькулятор/визуализатор/тренажер/генератор/гибрид — что выбрали и почему именно он]
Конкуренты слабые в: [2-3 конкретные слабости]
Мы добавляем: [2-3 фичи которых нет у них]
AI нужен: ДА / НЕТ — [одна строка почему]
```

6. **Немедленно запустить `/choose-domain [keyword]`** — он подберет и РЕАЛЬНО проверит свободные домены через API (не гадать имена от себя). Свои варианты домена НЕ предлагать — это работа choose-domain.
   Итог для Boris: выбрать из проверенных свободных → купить → скинуть агенту → `/build-site [keyword] [домен]`.
